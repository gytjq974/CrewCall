# 이 프로젝트에서 파일을 어디에 둘지 판단하는 법

새 파일의 위치는 **어느 저장소가 기능을 맡고, 그 안에서 어떤 패턴으로 코드를 나누는지**부터 보고 정한다. 모노레포여도 웹과 서버가 서로 다른 패턴을 쓸 수 있다. 멀티레포에서는 다른 저장소와 연결되는 공개 API나 패키지 경계를 따른다.

## 근거를 찾는 순서

1. **기획의 결정과 현재 구조를 찾는다.** 기획서나 기존 아키텍처 문서에서 저장소 구성, 대상 모듈, 개발 패턴과 허용된 의존 방향을 확인하고 이웃 기능과 대조한다. 문서가 없으면 빌드 설정과 실제로 사용 중인 대표 기능을 근거로 기존 패턴을 이어 쓴다. 폴더 이름 하나만 보고 저장소 경계를 단정하지 않는다.
2. **그 구조 안에서 도구가 요구하는 위치를 확인한다.** 해당 모듈의 지침·매니페스트·잠금 파일·빌드 설정에서 실제 소스와 테스트 루트, 공개 경로를 찾는다. 도구의 필수 조건인지 선택 가능한 기본값인지 불분명하면 사용 중인 버전·모드의 공식 문서를 확인한다. 프로젝트의 설정과 경로가 유효하면 그대로 쓴다.
3. **다음 작업에서도 찾을 수 있게 남긴다.** 코드 로드맵에 적용할 모듈, 실제 경로, 이유와 근거 파일을 짧게 적는다. 공식 문서가 판단을 바꿨다면 그 링크도 남긴다. 다음 채팅은 설정·버전이 바뀌었거나 새 모듈을 맡을 때 해당 항목을 다시 확인한다.

새 프로젝트에서는 기획에서 합의한 구조 안에 이번 기능에 필요한 폴더를 둔다. 열어 둔 세부 경로에 한해 도구의 기본 배치를 참고한다. 기획과 현재 구현이 다르면 적용 중인 결정과 전환 범위를 확인한다. 사용자가 이미 구조 변경을 요청했다면 합의한 범위에서 진행한다. 새로 저장소 통합·분리나 패턴 전환이 필요해지면 막히는 지점과 대안, 영향을 설명하고 그 변경만 사용자의 결정을 기다린다.

## 환경에 따라 달라지는 판단 예

| 환경에서 발견한 단서 | 실제로 내릴 판단 |
|---|---|
| Next.js App Router의 `app/orders/page.tsx` | 기본 설정에서는 `/orders` 페이지의 진입점이다. 공개 라우트를 유지하면서 내부 로직을 옮길 수 있다. 일반 컴포넌트는 팀이 선택한 위치에 둔다. [Next.js 프로젝트 구조](https://nextjs.org/docs/app/getting-started/project-structure) |
| Maven 모듈의 `pom.xml` | 자바 소스의 기본 경로는 `src/main/java`다. 해당 모듈의 빌드 설정이 다른 소스 루트를 지정하면 그 설정을 쓰고, 이동 후에는 모듈 빌드에서 소스가 포함되는지 확인한다. [Maven 표준 디렉터리 구조](https://maven.apache.org/guides/introduction/introduction-to-the-standard-directory-layout.html) |
| Python 배포 패키지 | 루트에 패키지를 두는 방식과 `src/` 아래 두는 방식이 모두 쓰인다. 패키징 설정과 설치 후 import 경로를 확인한다. 디렉터리 이름만 보고 구조 변경을 제안하지 않는다. [Python Packaging User Guide](https://packaging.python.org/en/latest/discussions/src-layout-vs-flat-layout/) |

파일을 옮겼다면 그 위치를 해석하는 경로를 직접 검사한다. 예를 들어 라우트는 기존 URL을, 패키지는 소비자가 사용하는 공개 import와 배포 결과를, 테스트 파일은 프로젝트의 테스트 명령이 실제로 발견하는지를 확인한다.
