# 결함이 있으면 원인을 좁힌 뒤 수정한다

“메모를 저장했는데 다시 열면 사라져. 원인만 봐줘”라는 요청을 예로 든다. 메인은 사용자가 허용한 범위에서 아래 과정을 따라 원인을 찾고, 확인한 내용을 보고한다. 이번 요청에 수정도 포함되어야 마지막 단계에서 코드를 고칠 수 있다. [작업 경로와 승인](../SKILL.md#작업-경로와-승인)

1. **무엇이 잘못됐는지 확인한다.** 어느 버전에서, 어떤 권한으로, 어떤 화면이나 기능을 이용했는지 살펴본다. 입력한 글, 기대한 결과, 실제로 본 결과를 기록한다. 같은 증상이 이미 실패 로그나 테스트에 남아 있으면 그 증거를 사용한다. 실제 데이터가 손상되거나 외부 시스템에 영향을 줄 수 있으면 원본 환경에서 실패를 다시 일으키지 않는다.
2. **값이 처음 달라진 곳을 찾는다.** 메모를 입력한 화면, 저장할 때 받은 값, 저장된 파일, 앱을 다시 열 때 읽은 값을 차례로 비교한다. 정상적으로 저장되는 메모가 있다면 같은 위치에서 값을 비교한다.
3. **가능한 원인을 하나씩 가려낸다.** 예를 들어 “파일에는 글이 있는데 다시 연 화면에서만 비면, 파일을 읽은 뒤의 과정을 살펴보자”라고 예상하고 그 차이를 확인할 가장 작은 검사를 한다. 예상이 틀리면 실제 값을 기록하고 다음 원인을 살핀다. 근거가 부족하면 확인한 사실과 아직 모르는 점을 나눠 보고한다.
4. **수정도 요청받았을 때, 원인이 확인된 곳을 고친다.** 재현할 입력이나 기존 테스트가 있다면 수정 전 실패부터 확인한다. 확인한 원인을 해결하는 데 필요한 부분만 고친다. 같은 문제가 다시 생긴 것을 기존 검사로 알아낼 수 없을 때는 계속 사용할 테스트를 추가한다. 그 사례를 독립 테스트 담당자가 맡았다면 재현 방법과 근거를 전달해 검사를 두 번 만들지 않는다.
