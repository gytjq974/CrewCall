# 설계 · 코드 지도와 기획 수정의 연결

[기획](plan.md) · [CrewCall 저장소의 실제 로드맵](../../code-map.md)

이 저장소에서 실행 동작을 결정하는 곳은 스킬의 Markdown 지침이다. 기존 planning.md는 변경 위치와 테스트 방법을 요구했지만, 기획 조건이 현행 데이터로 성립하지 않을 때의 처리와 공통 코드 지도는 정하지 않았다. project-state.md의 작업별 기획·설계 파일과 별개로, 프로젝트 전체가 공유하는 코드 로드맵 하나를 둔다.

| 바꿀 곳 | 확인할 동작 |
|---|---|
| SKILL.md, planning.md | 설계 요청을 받으면 로드맵을 확인하고 관련 원문을 조사한다. 근거가 부족한 경우와 현재 제약상 불가능한 경우를 구분한다. |
| collaboration.md, project-state.md | 다른 역할과 새 채팅이 같은 로드맵과 해당 작업의 완료 조건을 찾을 수 있다. |
| code-map.md, verification.md | 메인이 변경된 코드·검사 위치를 확인해 기존 지도에 반영하고 다음 작업에서 재사용한다. |

검증은 작성일 없는 메모의 날짜 복원 요구와, 기존 모듈을 호출하는 기능과 테스트가 추가되는 실습으로 한다. 기획 수정 전후의 파일과 로드맵의 관련 항목을 실제 결과와 대조한다.
