# CrewCall 최근 작업

## 필요한 범위의 탐색과 검증

2026-11-20에 **완료**했다. 0.9.8에서 검토한 여섯 가지 비용 요인을 조정하고 성능이 요구된 작업의 측정 기준을 보완했다. 단계별 기록·전체 DDL·필요한 독립 검토·사용자 실행 확인·짧은 한글 주석은 유지한다. 조회 기능의 주석 마무리와 검사 재사용, 역할 문서 생성, 성능 목표의 전후 측정을 실제 실행했고 형식·링크·버전과 변경분을 정적 검토했다. 미실행 변형과 결과는 [검증 기록](../development.md#필요한-범위의-탐색과-검증-시험)에 있다. 사용자 요청에 따라 검증한 변경을 커밋하고 원격에 반영한다.

## 리팩토링 한글 주석과 단순 작업의 바로 처리

2026-11-20에 **완료**했다. 0.9.7에서는 리팩토링 완료에 필요한 한글 주석 작성·정리를 포함한다. 함수 역할, 분기의 업무상 의미, 중요한 처리 이유를 짧게 남기고 자명한 내용과 장황한 함수 설명은 생략한다. 구조 변경이 없어도 주석을 점검한다. 단순 문구·값 수정과 요청한 Git 반영은 기획·설계 없이 바로 처리하며, 메인과 최근 구현 담당자 중 코드 재확인·인계·대기 비용이 적은 쪽이 맡는다. E-19 두 변형과 E-20 수정·선택 커밋을 실제 실행했고 E-21은 정적 검토했다. 토큰 사용량은 측정하지 않았다. [주석 지침](../../skills/crewcall/references/refactoring.md#코드에-남길-짧은-한글-주석) · [바로 처리하는 경로](../../skills/crewcall/SKILL.md#작업-경로와-승인) · [검증 결과와 미실행 범위](../development.md#리팩토링-한글-주석과-단순-작업-시험)

## 사용자 실행 확인과 개발 중 기획 변경

2026-11-20에 **완료**했다. 0.9.6에서는 구현과 필수 검증 후 사용자가 직접 실행한 결과에 만족하는지 확인하고 구조 점검에 들어간다. 개발 중이거나 결과를 확인하는 중에 기획 변경을 요청하면 기획서와 설계서를 갱신하고 구현을 이어간다. [사용자 실행 확인](../../skills/crewcall/references/verification.md#사용자가-직접-실행해-결과를-확인한다) · [개발 중 기획 변경](../../skills/crewcall/references/planning.md#개발-중-기획이-바뀌면) · [행동 시험](../development.md#사용자-실행-확인과-개발-중-기획-변경-시험)

## 프로젝트에서 정한 구조 우선

## 관계형 데이터베이스의 DDL 관리

2026-11-20에 **완료**했다. 0.9.3에서 관계형 DB의 전체 DDL을 코드 로드맵에 연결하고, 스키마 변경 시 같은 SQL 파일을 갱신하도록 했다. SQLite 실습에서 외래 키와 컬럼 변경을 대조하고 새 대화가 최신 정의로 집계 쿼리를 설계하는 것까지 확인했다. [데이터베이스 지침](../../skills/crewcall/references/database-schema.md) · [시험 결과](../development.md#db-구조를-기록하고-이어-쓰는-시험)
